# 关卡文件格式

## 1. 文件位置

```text
resources/levels/
├── levels.txt          # 关卡顺序清单
├── 01_labyrinth.txt
├── 02_corridors.txt
├── 03_core.txt
└── 04_line.txt
```

`resources/game_config.tres` 的 `level_manifest` 指向清单文件，默认是 `res://resources/levels/levels.txt`。

`levels.txt` 每行一个关卡文件，按书写顺序循环。空行以及 `//`、`;`、`#` 开头的行会被忽略。相对路径以清单所在目录为基准，也可以写完整的 `res://` 路径。文件名省略 `.txt` 时加载器会自动补全。

```text
// 关卡顺序
01_labyrinth.txt
02_corridors.txt
03_core.txt
04_line.txt
```

清完清单中的最后一关后，游戏回到第一关，`LOOP` 计数加一。全局 `wave` 继续增长，所以球速仍会逐关提高。

## 2. 基本结构

关卡文件是 UTF-8 文本，由两部分组成：

1. `grid:` 之前的键值配置。
2. `grid:` 之后的字符网格，每个字符是一个格子。

```text
// 注释
name = Demo
origin = 50, 128
brick_size = 34, 23
step = 39, 29

grid:
################
#..2........3..#
#..2..XXXX..3..#
#..2........3..#
################
```

`grid:` 之前的空行和 `//`、`;`、`#` 注释会被忽略。`grid:` 之后只有 `//` 和 `;` 是注释，因为 `#` 在这里表示砖块。

## 3. 配置项

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `name` | 空 | 关卡显示名，HUD 和过场提示会使用 |
| `auto_layout` | `true` | 按网格列数/砖块行数自动缩放并居中；`false` 时使用手动布局 |
| `fill_field` | `false` | 把网格铺满可玩区域；用 `.` 控制空位。需要先开启 `auto_layout` |
| `origin` | `50, 128` | 网格左上角的基准像素坐标；自动布局会覆盖 `x`，填满模式保留 `y` 作为顶部 |
| `brick_size` | `34, 23` | 单个砖块 / 网格墙的基准尺寸；自动布局会按需缩放 |
| `step` | `39, 29` | 相邻格子的基准间距；自动布局会按需缩放 |
| `hue_start` | `0.155` | `#` 砖块第一个砖块行的色相 |
| `hue_end` | `0.79` | `#` 砖块最后一个砖块行的色相 |
| `hue_jitter` | `0.012` | `#` 砖块每块的色相随机抖动 |
| `wall_thickness` | `12` | `+` 细墙的厚度（像素），实际会限制在格子尺寸的 80% 以内 |
| `random_carve_chance` | `0.0` | 每个砖块格被随机挖空的概率；默认关闭，保证编关结果固定 |
| `color.<符号>` | 无 | 覆盖某个砖块符号的颜色，例如 `color.2 = #ff8dd8` |
| `hp.<符号>` | `1` | 砖块耐久，例如 `hp.8 = 3`；默认 1 次击碎 |
| `wall` | 无 | 追加一个像素墙，格式 `x, y, w, h`，可重复 |

`color.<符号>` 的符号区分大小写。颜色支持 `#RRGGBB`、`#RRGGBBAA` 或 Godot 支持的颜色名。

`wall` 适合复刻非网格迷宫；网格里的 `+`、`X`、`=` 会按格子自动生成墙，其中 `+` 是自动拼接的细墙。

## 4. 网格符号

| 符号 | 含义 |
| --- | --- |
| `.` 或空格 | 空位 |
| `#` | 普通砖，颜色按行从 `hue_start` 渐变到 `hue_end` |
| `1` - `9` | 彩色砖，按数字顺序取内置调色板 |
| `A` - `Z`、`a` - `z` | 彩色砖，按字母顺序循环取内置调色板 |
| `+` | 细墙，按上下左右邻居自动拼接 |
| `X`、`=` | 整格墙，不可破坏 |
| 其他符号 | 彩色砖，按字符编码取内置调色板 |

内置调色板：

```text
1 / A  #ffd56a  金
2 / B  #ff8dd8  粉
3 / C  #78f4ff  青
4 / D  #c9ff72  绿
5 / E  #ff9b45  橙
6 / F  #9b8cff  紫
7 / G  #5be3c1  蓝绿
8 / H  #ff6b6b  红
9 / I  #7dd3fc  天蓝
```

数字 `1` 对应第一个颜色，`2` 对应第二个，依此类推。字母从 `A` 开始循环使用同一组颜色。没有在 `color.<符号>` 中单独配置时使用这套调色板。

同一个彩色符号始终得到同一种颜色；`#` 例外，它按行在 `hue_start` 和 `hue_end` 之间渐变。需要新的视觉分组时，换一个符号或显式配置颜色即可。

### 多段耐久砖

用 `hp.<符号> = N` 给某个砖块符号增加耐久：

```text
hp.8 = 3
hp.5 = 2

grid:
.8.5.
.....
```

- 默认 `hp = 1`，一次命中即碎。
- `hp.8 = 3` 表示符号 `8` 的砖块要命中三次才碎。
- 满耐久时砖块会显示加固边框和角点；每次命中后颜色变暗、增加裂纹，最后一击前出现金色警告边。
- 每次命中都会触发砖块震动、音效和粒子；只有真正碎裂时才增加 COMBO、充能 FIRE、掉落道具。
- FIRE RUSH 穿透时直接击碎耐久砖，不按剩余 HP 计算。
- `hp` 和 `color` 可以同时用于同一个符号。

### 细墙自动拼接

`+` 会检查上下左右四个邻居，自动生成需要的墙段：

```text
孤立 +      单线 +       拐角 +        T 形 +       十字 +
  ■          ───           ─┐           ─┬─           ─┼─
                           └─           │            │
```

- 只有相邻的 `+` 会互相连接，`+` 不会自动连到 `X` / `=`。
- `+` 格子本身不生成砖块，可以放在砖块区，也可以放在砖块区下方的空白行，只用来摆墙。
- 墙段默认厚度是 `wall_thickness = 12`，可用配置项调整。
- 相邻格之间的空隙会自动补上连接段，视觉和碰撞都是连续的。

当前所有非墙砖块的行为仍然一致：一次碰撞即破坏。符号目前决定“空位 / 砖块 / 墙”和砖块颜色；如果要加入多血量砖、爆炸砖等玩法类型，需要同时扩展 `BrickData` 和碰撞规则，不能只改关卡文件。

## 5. 网格规则

- 行数由 `grid:` 之后的行数决定，列数取最长行；列数、行数都不限制为 16 / 13。
- 默认开启 `auto_layout`：网格会按场地宽度和砖块行数自动缩放、水平居中，列数多的关卡不会被裁切。
- 推荐每行长度一致，方便人工检查。较短的行按空位处理，较长行会扩大列数。
- 空白行会被忽略，空行不能表示一整行的空位，请写 `................`。
- 砖块与 `wall` 重叠时，该砖块会被跳过；`LevelGenerator._intersects_wall()` 会额外留出 3 像素余量。
- 网格墙 `X` / `=` / `+` 不参与砖块生成，但会参与球的碰撞。
- `random_carve_chance` 默认是 `0`。只有需要每局变化时才开启。

### 自动布局

默认 `auto_layout = true`，有两种模式。

#### fit 模式（默认）

`fill_field = false` 时：

1. 从最长行得到列数，从最后一个含砖块的行得到砖块区高度。
2. 用一个统一缩放比例把网格塞进可用区域，不会放大小网格。
3. 水平居中；`origin.y` 保持不变，砖块区仍然从上方开始。
4. 同步缩放 `wall_thickness`，避免宽关卡里的细墙显得过粗。

可用宽度由 `game_config.tres` 的 `inner_left` / `inner_right` 和 `brick_area_margin` 决定，砖块区最大高度由 `brick_area_max_height` 决定。网格过宽或砖块行过多时自动缩小；列数较少时只居中，不拉伸。

#### fill 模式

关卡写 `fill_field = true` 时：

- 按网格列数把宽度铺满 `inner_left` 到 `inner_right`。
- 按网格总行数把高度铺满 `origin.y` 到 `brick_area_bottom`。
- `brick_size` 和 `brick_step` 分别在水平/垂直方向独立计算，砖块可能被拉宽或压扁。
- 想要四周留空，就在对应行列写 `.`。
- `brick_area_bottom` 在 `game_config.tres` 中配置，默认 `772`，给底部挡板留空间。

`04_line.txt` 使用 fill 模式，所以 24 列会填满左右，31 行会铺到设定底部。

需要精确手调 `origin` / `brick_size` / `step` 时，在关卡文件里写：

```text
auto_layout = false
```

注意：`wall = x,y,w,h` 是绝对像素坐标，不参与自动缩放；用 `+` / `X` / `=` 写在 grid 里的墙会随布局一起缩放。

## 6. 新增关卡

1. 在 `resources/levels/` 新建 `.txt`，按上面的格式写 `name` 和 `grid:`。
2. 把文件名追加到 `resources/levels/levels.txt`，决定它在循环中的位置。
3. 运行关卡测试：

```powershell
godot --headless --path . --script res://tests/level_test.gd
```

4. 运行游戏检查实际弹道和可读性。

删除关卡时，从 `levels.txt` 移除对应行即可。调整顺序只需要改清单，不需要改代码或 `.tres`。

## 7. 开发者跳关

`resources/game_config.tres` 的 `debug_tools` 打开时：

- `[` / `PageUp`：上一关
- `]` / `PageDown`：下一关
- `1`-`9`：跳到第 N 关（前 9 关）
- `Shift+R`：重开当前关
- `R`：重开整局

跳关会重建当前关卡、清空球和道具、回到待发射状态，并按关卡顺序刷新 `wave`。发布前把 `debug_tools` 设为 `false`。

## 8. 导出

Web / 桌面导出需要在导出预设的 `include_filter` 中包含文本关卡：

```text
resources/levels/*.txt
```

`export_presets.cfg` 已经配置了这一项。新增关卡目录时，同步修改过滤器，否则导出的游戏读不到文件。
