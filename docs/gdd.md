## 1. 产品概述

### 1.1 基本信息

- **名称**：Ricochet Labyrinth。
- **类型**：单人、竖屏、霓虹风格的打砖块 / 迷宫弹球游戏。
- **核心玩法**：移动挡板控制反弹，连续破坏砖块，触发多球与穿透冲刺，在不断加速的关卡循环中生存。
- **输入方式**：当前原型支持鼠标、键盘和触屏；正式发行平台尚未确定。
- **目标玩家**：喜欢打砖块、弹球、即时反应和连击挑战的玩家。
- **单局节奏**：短回合、可立即重开；具体局长与目标使用场景需通过测试确定。
- **视觉方向**：深色迷宫、霓虹砖块、弹道拖尾和程序化音效。

### 1.2 一句话介绍

**用一块挡板控制反弹角度，把一颗球打成满屏火力，在紧张救球与穿透清场之间不断切换。**

### 1.3 玩家幻想

玩家不是单纯“等到球掉下来再接住”，而是在做三件事：

1. 读懂墙面、障碍与砖块构成的反弹空间。
2. 用挡板的位置和移动影响下一次弹道。
3. 把连续的准确操作转化为多球和 FIRE RUSH，亲手制造一次清场爆发。

### 1.4 核心卖点

**“可控的混乱”**：平时需要精确判断，持续破砖会逐步带来多球、穿透和高密度反馈；持续回球、提速道具与后续关卡又会提高速度，把玩家带回下一轮救球压力。

这句话比“拥有多球、道具、粒子、震动等丰富系统”更适合作为卖点，因为它说明了系统组合后产生什么体验。

## 2. 为什么可能好玩

“好玩”不是文档替玩家下的结论，而是需要验证的设计目标。本项目用以下五条因果链支撑它。

### 2.1 易懂，但不是只能被动接球

- 玩家只需移动挡板和发射，初始理解成本低。
- 球的反弹方向受挡板接触位置影响，挡板移动也会改变出射方向。
- 场景障碍提供额外的反弹路径，玩家可以逐渐从“接到球”进步到“选择回球方向”。

**预期乐趣**：玩家能把结果归因于自己的判断和操作，产生“这次是我控得好”的胜任感，而不是只看随机弹道。

### 2.2 成长能直接改变场面，而不只是增加数字

- 连续接住球会累计 COMBO，并在阈值处奖励额外小球。
- 破砖同时为 FIRE RUSH 充能；满能量后自动进入 6 秒穿透状态。
- MULTI 会把场上小球翻倍，SPEED 会提高所有小球速度。

**预期乐趣**：玩家从一颗球开始，逐步看到球数、速度、颜色、声音和清砖效率共同升级。能力变化直接出现在核心操作中，形成可感知的“我变强了”。

### 2.3 紧张与释放交替，而不是全程同一强度

- 普通状态需要观察反弹、救球并维持连击。
- FIRE RUSH 中球可以穿透砖块，连续破砖带来短时释放。
- 冲刺结束后重新充能，开始下一轮积累。
- 关卡清空提供短暂停顿，随后以更高速度进入下一关；清完最后一关后回到第一关，速度继续提高。

**预期节奏**：

```text
观察与控球 → 连击积累 → 期待充能完成 → 穿透清场
     ↑                                      ↓
更高速度与救球压力 ← 冲刺结束 / 下一关 ← 短暂释放
```

### 2.4 增益同时制造新的风险

- 接道具需要移动挡板，可能离开原本适合救球的位置。
- SPEED 提高清场效率，也压缩反应时间。
- 多球提高清砖密度，并降低“所有球都漏掉”的概率；但当前规则中，任何一颗球漏出都会重置 COMBO。
- 每次挡板回球都会小幅加速，玩得越久，控制要求越高。

**预期乐趣**：玩家不只是领取无代价的奖励，而是在效率、位置和连击风险之间做快速取舍。

### 2.5 同时提供多个时间尺度的目标

| 时间尺度 | 玩家关注点 |
| --- | --- |
| 下一秒 | 球会落到哪里？该从挡板哪个位置回球？ |
| 接下来数次命中 | 要不要接道具？距离下一次多球或 FIRE RUSH 还有多久？ |
| 当前关卡 | 如何清掉剩余砖块？ |
| 整局 | 能保住连击和生命，推进到第几关、第几轮？ |

这些目标都来自同一套操作，不要求玩家额外学习菜单或复杂构筑。

## 3. 核心玩法

### 3.1 游戏目标

在生命耗尽前清除一关又一关砖块，尽可能维持 COMBO、推进关卡，并体验更高效的多球与 FIRE RUSH 清场。

当前原型有按清单循环的关卡流程，但没有最终通关点；生命耗尽后本局结束。也没有独立总分或排行榜，不能把它描述为已经具备完整分数竞争体系。

### 3.2 核心循环

```text
移动挡板 / 发射
        ↓
判断弹道并回球
        ↓
击毁砖块、躲避失误
        ↓
累计 COMBO、XP 与 FIRE 能量，产生道具掉落
        ↓
选择是否移动接取道具
        ↓
获得多球、加速或穿透爆发
        ↓
更快清场，同时面对更高信息量与速度
        ↓
清空本关 → 短暂停顿 → 更快的新关卡
```

生命耗尽后，本局结束；玩家可立即重新开始。

### 3.3 操作

| 行为 | 鼠标 / 触屏 | 键盘 |
| --- | --- | --- |
| 移动挡板 | 左右移动 / 拖动 | `A` / `D` 或左右方向键 |
| 发射球 | 左键 / 点击 | `Space` / `Enter` |
| 重新开始 | — | `R` |
| 游戏结束后重开 | 左键 / 点击 | `Space` / `Enter` |

发射角度在当前原型中带有随机性；持续控球的主要技巧来自挡板接触位置、挡板移动和对障碍反弹的预判。

### 3.4 玩家反复做的决定

| 情境 | 稳妥选择 | 激进选择 |
| --- | --- | --- |
| 球接近挡板 | 用中部回球，保留较稳定的弹道 | 用边缘或移动挡板，争取更合适的方向 |
| 道具下落 | 留在球的预测落点 | 偏离原位接取增益 |
| 多球状态 | 优先保证仍有球存活 | 为维持 COMBO，冒险抢救边缘球 |
| 高速状态 | 先恢复可控局面 | 利用高速度继续快速清砖 |

这里的设计重点不是选择数量，而是选择发生在同一个动作里：移动挡板既可能接球，也可能改变回球质量。

## 4. 当前规则与关键数值

> 下表记录当前原型的初始规则，用于统一讨论，不代表最终平衡结果。

### 4.1 场地、球与挡板

- 逻辑分辨率为 `720 × 920`，采用竖屏场地。
- 小球从挡板附近发射，初始基础速度为 `470`。
- 每进入下一关，基础速度增加 `18`。
- 球与左右墙、顶墙、静态障碍和普通砖块发生反弹。
- 球从底部漏出即为丢球。
- 挡板接触位置决定基础回球角度，挡板速度会额外影响水平出射方向。
- 普通挡板回球会小幅加速；每次墙面、障碍或砖块反弹也会增加 `1.5` 速度，所有来源最终受 `1410` 上限限制（初始速度 `470` 的 3 倍）。SPEED 道具也遵守该上限。
- 每次挡板接球都会让挡板变长 `10` 像素，最大宽度为当前关卡的砖墙宽度；挡板颜色随已扩展的宽度逐级变亮，并触发升级闪光。成长跨关卡保留，重开整局后重置。
- 挡板越宽移动越慢：基础移动速度 `760`，到最大宽度时降到 `580`；挡板缩回后速度按比例恢复。
- 任意小球掉落时，挡板的额外宽度减少 `2/3`，即只保留原有扩展量的 `1/3`；基础宽度不变。

### 4.2 生命与失败

- 一局开始有 `5` 点生命。
- 多球状态下，单颗球漏出会增加 LOST 计数并清空 COMBO，但不立即扣除生命。
- 只有场上所有球都漏出，才扣除 `1` 点生命。
- 若仍有生命，短暂等待后回到待发射状态；生命归零则本局结束。

因此，当前 HUD 中的 `BALLS` 是场上球数，`LOST` 是累计漏球数，二者都不等同于剩余生命。剩余生命缺少独立、醒目的展示，是首局可用性测试需要重点观察的问题。

### 4.3 砖块与关卡

- 示例关卡为 `16 列 × 13 行` 的砖块区域，行列和格子尺寸可按文件配置。
- 文本网格中的镂空、静态障碍和不同砖块符号共同构成迷宫式反弹空间；需要额外变化时可在文件里开启随机空格。
- 关卡布局来自 `resources/levels/*.txt`，由 `resources/levels/levels.txt` 决定顺序。
- 文本网格用符号描述内容，`#` 是行渐变砖，数字和字母是彩色砖，`+` 是按邻居自动拼接的细墙，`X` / `=` 是整格墙。
- 用 `hp.<符号> = N` 可定义多段耐久砖；砖块满耐久时有加固外观，受损后出现裂纹和震动，FIRE RUSH 可直接击碎。
- 清空当前关卡后进入 `CLEARED`，倒计时结束进入下一关；清完最后一关后回到第一关，`LOOP` 计数增加。
- 全局 `wave` 持续增加，球速随 `wave` 提高，因此循环后压力继续上升。

当前关卡由运营维护的文本文件定义，不是每局生成一张全新迷宫。进入下一关时 COMBO 会重置，不提供跨关卡的连击收益。

### 4.4 COMBO 与额外小球

- 每次挡板接住球，COMBO `+1`；破砖本身不增加 COMBO。
- COMBO 增加时右上角数字会弹跳并轻微抖动；达到 `10 / 30 / 50 / 100 / 200 / 500` 时字号逐级放大。
- 任意一颗球漏出、或进入下一关时，COMBO 重置。
- 首次达到 `30 COMBO` 时奖励额外小球，之后每增加 `35 COMBO` 再触发一次。
- 连击奖励会把球数推进到最多 `6`；MULTI 道具另有更高上限。

当前 COMBO 本质上是“未丢球期间的挡板接球次数”，不是破砖计数，也不是独立总分或伤害倍率。

**COMBO 与经验**

- 每次挡板接球获得经验：`1.0 + COMBO × 0.05`，接球连击越高，单次经验越多。
- 右上角显示当前 `COMBO` 和对应的 `XP +` 数值。
- 底部 XP 条满后升级，当前小球数量翻倍，受 `24` 球上限限制。
- 首次升级需要 `150` XP，之后每级需求乘以 `1.4`。
- XP 跨关卡保留，重开整局后清空；COMBO 仍然会在漏球或进入下一关时重置。

### 4.5 FIRE RUSH

- 普通破砖会为 FIRE 能量充能，每块增加 `3.4`，能量上限为 `100`。
- 按当前数值，连续破坏约 `30` 块普通砖可触发一次。
- 满能量后自动开始，持续 `6` 秒，不需要额外按键。
- 持续期间，球穿透砖块而不被砖块反弹；破砖不增加 COMBO。
- 场地边界与静态障碍仍会阻挡、反弹小球。
- 冲刺结束后能量清零，重新积累。

自动触发保证规则简单；是否需要主动触发、是否增加触发决策，应在核心手感验证后再评估，而不是直接增加操作。

### 4.6 道具

| 道具 | 当前效果 | 体验作用 |
| --- | --- | --- |
| `MULTI` | 当前所有小球各复制一次，总球数上限 `24` | 快速放大清场能力与视觉密度 |
| `SPEED` | 所有小球速度提高 `18%`，速度上限 `1410` | 提高效率，同时增加反应压力 |

掉落规则：

- 普通状态基础掉落率为 `14%`。
- FIRE RUSH 中掉落率乘以 `0.72`，即基础概率约为 `10.08%`。
- 连续判定达到 `8` 次时触发保底。
- 场上最多同时存在 `7` 个待接取道具。
- 道具向下运动，玩家需要让挡板接触道具才能生效。

## 5. 关卡与难度设计

### 5.1 迷宫的作用

迷宫不是装饰。固定障碍改变球路，使同一套打砖块规则产生不同的空间问题：

- 球可能进入砖块与障碍形成的通道，连续反弹。
- 下部障碍会改变返回挡板前的路线，要求玩家重新判断落点。
- 局部镂空让球进入砖阵内部，也给玩家提供观察和理解空间的机会。

### 5.2 难度来源

当前难度主要来自四项叠加：

1. 关卡循环推进后的基础球速。
2. 挡板回球、墙面/砖块反弹与 SPEED 道具带来的进一步加速。
3. 多球造成的注意力分配压力。
4. 障碍反弹造成的弹道变化。

后续调参应分别测试这四项，不应只靠全面提高速度制造难度。若玩家频繁认为“球路不可读”或“失败不是自己的责任”，应优先检查可读性和操作反馈，而非继续增加内容。

## 6. 反馈与界面

| 事件 | 当前反馈 | 设计目的 |
| --- | --- | --- |
| 发射与回球 | 音效、挡板变长、升级闪光与 `WIDTH +10` 漂浮字 | 让玩家确认接球并看到挡板成长 |
| 破砖 | 砖块消失、闪光、粒子、漂浮计数 | 建立动作到结果的直接联系 |
| COMBO 增加 | 右上角数字弹跳/抖动，按阈值放大的字号 | 让每次接球都有即时反馈 |
| COMBO 达标 | 数字强调、右上角 XP 收益、`MULTIBALL` 提示 | 让积累与奖励形成清晰因果 |
| XP 满条 | 底部经验条闪光、升级音效、当前球数翻倍 | 给连击一个阶段性目标 |
| 道具出现 / 接取 | 独立颜色、运动、拾取文字与音高 | 在密集场面中识别机会 |
| FIRE 充能 / 触发 | HUD 百分比、橙色状态、冲刺提示 | 先建立期待，再兑现爆发 |
| 丢球 / 游戏结束 | 危险色、震动、状态提示 | 解释失败并给出重开入口 |

HUD 持续回答四个问题：当前第几关/第几轮、清除多少、COMBO 多少、FIRE 还要多久或还能持续多久。

表现层应优先突出球、危险落点和关键状态。多球与粒子同时增多时，需要测试装饰效果是否遮挡真实弹道。

## 7. 理想首局体验

这是一段体验脚本，不是已经得到验证的新手流程：

1. **看懂目标**：玩家看到砖块、挡板和发射提示，不经口头说明完成发射。
2. **获得第一次成功**：球击中砖块，画面和声音立即响应，COMBO、清除率和 FIRE 能量发生变化。
3. **发现自己能控球**：玩家通过不同接触位置改变回球方向，而不只是左右追赶。
4. **遇到一次取舍**：道具下落，玩家决定是否离开当前救球位置。
5. **获得第一次爆发**：FIRE RUSH 或多球让清砖效率明显提升。
6. **理解一次失败**：玩家知道是漏球导致 COMBO 清零，或全部球漏出导致生命减少。
7. **产生再试一次的动机**：玩家能说出下一局准备改进什么，例如更早预判、减少危险接球或更稳地维持 COMBO。

如果第 2、3、5 步没有发生，增加新砖块、剧情或外围成长通常不能解决核心问题。

## 8. 当前范围与非目标

### 8.1 当前已经具备

- 可操作的挡板、发球、反弹、丢球和重开流程。
- 文本定义的多关卡循环与静态障碍布局。
- 随接球逐渐变长的挡板，以及带裂纹/震动阶段的多段耐久砖。
- 循环关卡、COMBO、经验升级、额外小球和 FIRE RUSH。
- MULTI、SPEED 两类道具及保底掉落。
- 霓虹拖尾、粒子、震动、漂浮文字和程序化音效。
- 可独立测试的核心模拟与固定随机种子。

### 8.2 当前不应宣称已经具备

- 独立总分、最高分记录或排行榜。
- 持久成长、解锁、剧情、关卡选择或最终结局。
- 完整新手教程、商业化、账号、联网或社交系统。
- 已验证的单局时长、留存、付费意愿或市场规模。

### 8.3 后续候选，而非开发承诺

核心体验验证通过后，再按问题选择扩展：

- 若缺少长期目标，再研究分数、排行榜或每日挑战。
- 若关卡循环后仍显重复，再增加更多关卡或经过区分的砖块行为、障碍组合。
- 若失败原因不清，再改进危险提示、弹道可读性和剩余生命展示。
- 若高球数影响操作，再调整表现密度、球数上限和速度曲线。

“可以加入什么”不是立项重点；“核心测试暴露了什么问题，为什么这项扩展能解决”才是。

## 9. 验证计划：把“好玩”变成证据

首轮建议邀请 `5–8` 名目标类型玩家做观察测试，用于发现明显理解与控制问题。这样的样本不能证明市场规模，也不能替代正式留存测试。

以下是通过标准示例，**不是项目已经取得的数据**：

| 假设 | 测试方法 | 示例通过标准 |
| --- | --- | --- |
| 玩家能快速理解基本操作 | 不做口头教学，记录首次发射和首次成功回球 | 80% 玩家在 15 秒内完成发射 |
| 回球具有可学习的控制感 | 第一关后询问并观察玩家是否主动选择接触位置 | 70% 玩家能说明并演示接触位置对方向的影响 |
| FIRE RUSH 形成期待与回报 | 观察充能阶段和首次触发后的复述 | 80% 玩家能说明如何触发、触发后有什么变化 |
| 失败原因可理解 | 每次明显失误后询问“为什么丢了 / 为什么扣生命” | 80% 玩家的解释与规则一致 |
| 核心循环有即时重玩吸引力 | 首次 GAME OVER 后不主动催促，观察选择 | 50% 玩家主动立即重开至少一次 |

测试时同时记录：首次 FIRE RUSH 时间、单关时长、单局时长、丢球原因、速度、最高球数、是否接取道具和重开次数。后续才能判断问题来自操作、规则理解、难度曲线还是内容重复。

“主动重开一次”只能支持即时吸引力假设，不能直接包装成次日留存、长期黏性或付费潜力。

## 10. 从 GDD 转成立项书与投资材料

GDD 回答“做什么、怎么玩、如何制作和验证”；投资材料还要回答“为谁做、为什么是现在、团队凭什么做成、如何形成业务、资金换来什么里程碑”。一份 GDD 不能单独替代商业计划。

### 10.1 可以复用的内容

| GDD 内容 | 立项 / 路演中的用途 |
| --- | --- |
| 一句话介绍 | 让听众迅速理解产品，不先讲技术架构 |
| 核心循环与 10–15 秒实机画面 | 证明游戏确实可玩，展示最核心的紧张—爆发变化 |
| 为什么好玩的因果链 | 解释差异化来自哪些系统互动，而非功能堆砌 |
| 当前范围与非目标 | 证明团队知道先做什么、不做什么 |
| 验证计划与后续真实结果 | 把“我们觉得好玩”改成“哪项假设得到了什么证据” |

### 10.2 仍需另行补齐的内容

1. **目标用户与使用场景**：谁在什么情况下会选择它，依据是什么。
2. **竞品与替代品**：不仅列产品名，还比较核心体验、平台、价格、内容量和用户评价。
3. **市场证据**：使用可追溯来源，注明统计口径与日期；不能用虚构的 TAM 或收入填充页面。
4. **商业模式**：买断、免费加内购或其他模式，需要与目标平台、内容结构和获客方式一致。
5. **产品验证**：实机测试、愿望单、下载、留存或付费数据分别能证明什么，不能证明什么。
6. **制作计划**：团队、人员缺口、里程碑、外包依赖、测试与发行风险。
7. **融资请求**：需要多少钱、用于哪些岗位和月份、到达哪个可检查里程碑，而不只写“用于研发和推广”。

### 10.3 一段不虚构数据的路演示例

> Ricochet Labyrinth 是一款竖屏霓虹打砖块游戏。玩家用挡板接触位置和移动控制回球，在连续破砖中积累多球与 FIRE RUSH，把精确救球转化为短时间的穿透清场。项目的核心不是单纯增加砖块和道具，而是用同一套移动操作连接控球、接取风险和场面成长，让紧张与释放交替出现。
>
> 当前可玩原型已经打通发球、反弹、关卡循环、连击、多球、道具和冲刺流程，因此下一阶段可以直接验证核心体验，而不是先投入大量外围内容。我们计划先测试玩家是否理解控球、是否期待并享受 FIRE RUSH、是否理解失败原因，以及是否愿意主动重开；只有这些假设得到支持，才扩展长期目标和更多关卡。
>
> 目标市场、商业模式、制作预算和融资金额需要用真实研究与计划另行补齐。本轮资金若进入正式讨论，应对应到明确的人员、时间和验收里程碑，例如“完成多少轮目标用户测试、达到什么核心体验指标、交付什么版本”，而不是只用‘把游戏做完’作为资金用途。

这段话术的重点是诚实地区分：原型只证明“核心规则已经能运行”，用户测试将帮助判断“核心体验是否成立”；完整项目的交付能力仍需团队与制作计划支撑，市场和单位经济模型也需要其他证据。

## 11. 立项检查清单

提交前逐项检查：

- [ ] 一句话中是否同时包含玩家动作和独特体验？
- [ ] 核心循环能否在一屏内画完，并回到自身形成循环？
- [ ] 每个设计支柱是否都有实际规则支撑？
- [ ] “为什么好玩”是否写成了机制 → 玩家决策 → 情绪 / 体验的因果链？
- [ ] 是否明确区分现状、设计目标和未来候选？
- [ ] 数值是否能与当前原型对应，失败和奖励条件是否有歧义？
- [ ] 是否写出了验证方法，而不只是写“后续持续优化”？
- [ ] 是否避免用功能数量代替差异化？
- [ ] 是否避免把主动重开、访谈好感或竞品成绩夸大为留存和收入保证？
- [ ] 对投资人是否补齐了市场、团队、商业模式、预算、里程碑和融资用途？
